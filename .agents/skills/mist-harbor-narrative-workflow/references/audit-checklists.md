# 可玩叙事审计清单

按当前任务取用，不要把所有清单机械套在每个短任务上。

## 场次与行动链

- [ ] 目标、玩家已知事实和进入条件可定位。
- [ ] 每个关键选择能写出玩家意图，而不是只有语气差异。
- [ ] 选择前没有替玩家完成撒谎、承诺、公开、撤回或关系升级。
- [ ] NPC 回应后至少有一处继续、改招或退出的真实控制权。
- [ ] 选择后的反馈可被玩家看到、听到或由下一项可用动作体现。
- [ ] 另一意图路径保留了可观察差异，合流没有抹去知识或承诺。

## 状态与信息释放

- [ ] 每个变量有默认值、写入点、读取点、寿命和重置语义。
- [ ] 世界事实、角色知识、玩家知识、技术/UI 状态分开。
- [ ] 未选分支、作者备注和 NPC 未证实说法没有泄漏进玩家知识。
- [ ] 回退、重进、跳过和重复点击不会重复发放后果。
- [ ] 每条线索能指出来源、见证者、披露对象、验证状态和后续读取者。
- [ ] 未定事项保持“待确认”，没有被实现便利补成结论。

## 运行器与数据

- [ ] 对白文本不在 GDScript 中硬编码。
- [ ] 下一节点/话题 ID 存在、可达，且条件冻结后仍有合法去向。
- [ ] 未满足条件的选择不可见；条件变量先初始化。
- [ ] 状态变更属于状态层，UI 只呈现和发出事件。
- [ ] 当前入口明确，v6 与 R16.2 不混用。
- [ ] `content/程序生成_请勿手改/` 未被手工修改。

## 连续性与交付

- [ ] 时间、地点、在场人物、称谓和公开口径与 v6 权威文件一致。
- [ ] 问题/承诺有提出、接受、改约、取消、错过或兑现状态。
- [ ] 至少完整跟读一条主路径和一条不同意图路径。
- [ ] 报告区分事实、实现观察、推断、建议、失败测试和未验证项。
- [ ] 涉及正式内容时，报告用户确认门、`DECISIONS.md` 和同步链状态。

## 首次玩家可理解性

- [ ] 首个关键画面能让玩家推断当前目标。
- [ ] 选项表达可执行的不同意图和风险。
- [ ] 操作后有具体反馈，而不是只更新隐藏变量。
- [ ] 观察记录来自真实操作路径，不用作者知识补全。
- [ ] 缺少构建、重放或状态证据时，结论标为“待验证假设”。

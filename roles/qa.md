# QA｜质量验证角色

## 职责

- 验证剧情数据、交互流程、知识状态、章节切换、回退行为和工作簿同步流程。
- 检查重复 ID、无效引用、不存在的下一场景、不可达分支、条件错误、变量错误、缺失资源和旧内容残留。
- 执行启动测试与回归测试，并区分实现缺陷、数据缺陷和过期测试。
- 检查正式设定与当前实现之间是否存在可复现的不一致。
- 按玩家路径验证：只有实际点击、看见或听见的内容才进入玩家知识。
- 报告缺陷时提供最短复现步骤、预期结果、实际结果、证据和影响范围。

## 禁止事项

- 不得在验证过程中修改剧情、代码、工作簿或生成数据来让测试通过。
- 不得把测试失败自动解释为剧情错误；必须先判断是需求、数据、实现还是测试口径问题。
- 不得把待定设定当作测试预期。
- 不得手工编辑 `content/程序生成_请勿手改/剧情剧本.csv`。
- 不得只验证理想主线；必须覆盖未点击、乱序、回退和章节隔离等负向路径。
- 不得在缺少证据时宣称通过或失败。

## 必须读取的资料

1. `README.md`
2. `docs/CURRENT_TRUTH.md`
3. `docs/剧情修订稿_v6_人物与前史.md`（涉及作者层设定时）
4. `docs/雾港来信_序章与第一章完整剧情信息树_v6.md`（涉及序章或第一章时）
5. `docs/DECISIONS.md`
6. `content/剧情表使用说明.md`
7. `content/秘密释放与AI资源审查.md`
8. 与任务相关的测试、脚本和剧情数据


## 验收标准

- 所有结论均可由命令输出、稳定 ID、界面行为或文件内容复核。
- 覆盖正常路径以及未点击、乱序、回退、重进和章节切换等关键边界。
- 单独检查秘密提前释放、玩家知识越界和证据持有状态。
- 明确区分测试失败、环境阻塞、资料冲突和未验证项。
- 报告不包含未经确认的剧情结论，也不对现有文件做修复性修改。

## 必须停止并报告的情况

- 测试预期与权威文件冲突，或权威文件缺失导致预期无法建立。
- 测试会覆盖工作簿、CSV、存档或其他用户文件，且没有隔离副本或回滚方式。
- 只能通过篡改剧情事实、降低正确校验或删除失败用例来获得通过。
- 环境、资源或依赖缺失，使结果无法可靠复现。

# 《雾港来信》美术资产生产流程

> 目标：建立可追踪、可复用、可进入 Godot 的美术生产闭环。  
> 当前阶段：只建立基础设施，不生成新角色、新场景、新 UI 或新 CG。

## 1. 标准流程

```text
剧情需求
→ 查 docs/VISUAL_BIBLE.md
→ 查 docs/CHARACTER_STYLE_GUIDE.md
→ 查 production/characters/ 与角色标准板
→ 查地点母版
→ 生成 shot list
→ 判断哪些镜头可以复用
→ 建立 asset task
→ GPT 负责美术规划 / 提示词 / 图像生成与审查
→ Codex 负责命名 / 归档 / manifest / Godot 导入 / 缺失检查
→ QA
→ 通过后锁定版本
```

任一上游权威文件、角色标准板或地点母版缺失时，受影响任务标记为 `todo` 或“待确认”，不得用代码、旧图、类型惯例或文字猜测补齐。

## 2. 需求进入

每条美术需求至少写明：

- 对应章节、场次与 story state。
- 出现的角色、地点、道具与镜头类型。
- 允许修改范围与禁止范围。
- 需要引用的角色标准板、地点母版与已有资产。
- 验收方式、输出尺寸、分层要求与目标导入位置。

剧情事实必须先从 `docs/CURRENT_TRUTH.md` 与 `docs/剧情修订稿_v6_人物与前史.md` 读取。具体场次、顺序与台词必须等待缺失的剧情信息树 v6 恢复后再核对。

## 3. Shot list 与复用判断

不要逐句对白生成完整 CG。先把镜头拆成可复用层：

1. 场景母版。
2. 人物分层。
3. 道具分层。
4. 灯光 / 前景 / 雾气。
5. Godot 内的镜头运动、遮罩、转场与复用。

shot list 必须先回答：

- 是否能复用现有地点母版，仅改变裁切、景别或机位？
- 是否能复用人物立绘，仅替换行为状态、朝向或手持物？
- 道具是否需要独立层，还是已经包含在角色/场景母版中？
- 雾气、灯光和前景是否可在 Godot 中叠加，而不是烘焙成新 CG？
- 当前镜头是否真的需要一次性整张图？

## 4. Asset task

每个任务对应 `production/asset_manifest.csv` 中的一行或一组关联行。创建任务时至少填写：

- 稳定的 `asset_id`。
- 资产类型、角色或地点、章节/场次、镜头类型与 story state。
- 源参考与目标文件路径。
- 状态、优先级、版本与待确认事项。

一个资产进入生成前必须能追溯到需求和参考，进入 Godot 前必须能追溯到已批准版本。

## 5. GPT 职责

- 把已确认需求转成美术规划、构图说明、分层方案和提示词。
- 每次生成或编辑都引用 Visual Bible、Character Style Guide、角色标准板、地点母版和 metadata。
- 已有标准板时优先编辑现有图，不从纯文字重设计。
- 对比例、脸、服装、道具、行为状态、年代与善恶编码进行首轮审查。
- 发现资料冲突时停止受影响内容，列出冲突并标记“待确认”。

## 6. Codex 职责

- 按命名规范归档源图、过程稿、批准稿与弃用稿，不静默覆盖。
- 维护角色 metadata 与 `production/asset_manifest.csv`。
- 检查引用路径、重复 ID、缺失文件、状态和值域。
- 在获得批准后执行裁切、格式转换、Godot 导入与资源引用同步。
- 运行导入检查、缺失检查和相关测试；把过期测试与真实缺陷分开报告。
- 不为了通过检查而修改剧情事实或美术设定。

## 7. 状态与版本

允许状态：

- `todo`：需求已登记，尚未制作。
- `draft`：工作稿或视觉母版，未批准锁定。
- `revise`：已审查，需要修正。
- `approved`：单项输出已批准，可进入集成，但尚未成为不可漂移的长期基准。
- `locked`：已确认的长期基准版本。
- `deprecated`：已撤销或被取代，只保留追溯。

版本升级不得覆盖旧文件。文件名、metadata 与 manifest 必须同时指向当前版本；旧版本改为 `deprecated` 并保留取代关系说明。

## 8. QA

### 事实与引用

- 年龄、身份、年份、服装与道具均能追溯到权威文件或已确认决策。
- `master_reference`、`source_reference` 与 `file_path` 实际存在。
- 未确认内容保留“待确认”，没有从标准板画面或旧实现反推剧情事实。

### 视觉一致性

- 瘦长比例、低面部细节、低眼睛信息量保持一致。
- 行为状态清楚可辨，不是喜怒哀乐表情包。
- 服装符合年代和职业，旧化不过量。
- 无反派、正派、受害者或秘密角色的提前编码。
- 无现代商业插画、乙女游戏、偶像剧、二次元或照片写实漂移。

### 技术与集成

- 文件命名、格式、尺寸、透明通道和分层符合任务要求。
- manifest 中无重复 `asset_id`，状态和值域合法。
- Godot 导入无缺失、错误引用或意外重导入。
- 运行时只引用 `approved` 或 `locked` 资产；例外必须显式记录。

## 9. 锁定条件

只有同时满足以下条件才能标记 `locked`：

1. 项目负责人明确确认。
2. 角色/地点事实与权威资料一致。
3. 视觉审查与技术 QA 均通过。
4. 决策记录、metadata、manifest 和实际文件路径已经同步。
5. 被取代版本已保留并标记为 `deprecated`。

- P1：小六、编辑、版面编辑、门房 / 场务等可复用 NPC。

- 白素秋情人不出场。

# 《雾港来信》剧情表使用说明｜开场 Demo

## 修改剧情的固定流程

1. 双击项目根目录的 `打开剧情工作簿.command`。
2. 只修改工作簿中的“剧情剧本”页。
3. 保存并关闭工作簿。
4. 双击 `同步剧情工作簿.command`。
5. 看到同步完成后，重新运行 Godot Demo。DEC34 当前为 107 行；以后新增剧情会相应增加。

唯一编辑入口：

`outputs/01a037d8-c4f0-70d3-bc69-8c3819094801/雾港来信_剧情作者工作簿.xlsx`

`content/程序生成_请勿手改/剧情剧本.csv` 是游戏运行数据，不需要打开，也不要手动修改。

序章使用“场景探索”与“探索热点”：玩家可任意顺序点击物件。“春和”工作夹、二十年前旧报、采访函留底、赵敬文死亡报道与旧戏院草图组成四项出发检查；第四项关闭后直接显示函件准备选项，不再进入自动推断的独白。出现条件使用“已查看/尚未查看”的中文写法，不需要作者维护技术 flag。

## 当前运行流程

《雾港日报》五句退稿与派活 → 赵敬文工作桌四项检查 → 三种函件准备 → C01 戏院门前 → C04 林怀安采访 → 公开位置观察与《夜渡》 → C08—C16 命案、调查和警方笔录 → C17—C20 写稿与交稿 → C21 次日见报 → C22《夜渡》章末。

- NPC 台词按句主动阅读；轮到主控回应时保留当前 NPC 语境，按钮显示实际要说的话，点击后直接接对方回应，不重复播放主控句。单句必要回答也要点击，不得定时自动播放。场景动作、纯画面、写稿和见报结果走背景 UI；整页材料不按句分页。
- 工作桌四项检查完成后，带作者标记的场景行动直接进入函件准备；不编写主控替玩家总结材料的过场。
- 连续对白使用“NPC台词”类型，“是否说出口”填“是”；其中的 `沈砚舟：「……」` 会成为实际回应按钮。有取舍时使用“玩家选项”行分别写出具体回答、条件和下一话题。内心与材料使用各自类型，不作为主控发言。
- C04 原件路径在林询问桌面材料后，分别写“透露旧报与草图”和“只谈函件”的实际台词及当场回应；原件去留另选。C14 观察回答只按已选 C07/C09 信息显示，未看见的内容不能补全。
- 函件准备、公开位置、第一眼、警前调查、警方笔录、现场收束观察、稿件疑点和是否公开关联赵敬文都会留下后果。第三项函件路线不携带纸面：见林怀安只口述，警方登记口述并安排之后去报馆核验。
- 后台仍使用 Topic/Stage、Knowledge 和中文剧情状态；正式玩家看不到技术字段。

## 写作硬规则

1. 玩家没点，沈砚舟就没说。
2. 玩家没亲耳听见或亲眼看见，就不能写入玩家知识。
3. NPC 提问后，轮到沈砚舟回应时必须暂停。
4. 画面可以表达的内容写入“画面表现”，不要改成旁白。
5. 多选必须改变知识、状态、后续台词、证物控制或结局。
6. 当前 Demo 不提前揭露陈九生换药、周明远或旧案完整因果；只呈现 v6 C01—C22 明确写出的可观察事实与台词。
7. 修改已有台词不会改变自动 ID；新增行可以暂时留空，交给同步器生成。
8. 复杂动作与发言人分行写，例如先写“玉棠在通道里喊。”，再写 `林玉棠：「爹！」`。群众可用“有人”“另一人”等原有匿名称呼，不为解析方便增加姓名或身份。

## 当前表现范围

正式 UI、背景、立绘和道具图暂不制作。游戏使用 Godot 色块、文字、立绘框、画面演出提示和怀表占位，只验证剧情逻辑与选择路径。

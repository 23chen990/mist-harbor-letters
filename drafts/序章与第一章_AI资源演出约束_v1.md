# 《雾港来信》序章与第一章 AI 资源演出约束 v1

> 状态：工作制作方案；不构成正式剧情、正式美术或实现决策。  
> 审查对象：`drafts/序章与第一章_工作草案_v16.md`。  
> 依据：`docs/VISUAL_BIBLE.md`、`docs/CHARACTER_STYLE_GUIDE.md`、`production/ART_PIPELINE.md`、`production/asset_manifest.csv`、当前角色标准板与 Godot 占位实现。  
> 边界：本轮不修改剧情正文，不生成新图，不新增镜头、动画、UI、manifest 任务或运行时资源。

## 1. 总体判断

序章与第一章不能按“逐句对白配一张图、重要动作做连续动画”的方式生产。AI 资源的稳定单位应是：

```text
地点母版
＋ 可复用人物行为状态
＋ 独立道具层
＋ Godot 裁切、推拉、遮罩、灯光与前景
＋ 少量经过批准的关键静帧
```

本作的镜头价值来自玩家决定看哪里、角色在压力下如何回应，以及某句话最终怎样见报；不来自角色持续走动、精确口型或复杂肢体表演。

当前已有九名主要角色的正式标准板或正式图，但它们不等于可直接导入游戏的立绘切图。当前没有正式地点母版、正式 UI、正式道具层或正式动画资产；`asset_manifest.csv` 主要登记角色标准板。现阶段只能把本文件用于镜头预算与后续 asset task 拆分，不能声称正式美术链已经完成。

### 当前实现与目标能力必须分开

当前 Godot Demo 仍是 `Control`、色块、标签、按钮和文字占位：没有可用的 `TextureRect`／角色 Sprite 演出层，没有场景摄像机，没有裁切推镜、前景遮罩、淡入淡出、Tween 或场次镜头解释器。因此，下文的 A 档不是“现在免费就有”，而是后续最值得先补的最低共用能力。

建议未来只做一套很窄的镜头语法，不为每场写独立程序：

```text
背景 <地点ID> [变体]
角色 <角色ID>:<行为状态> @<锚点> scale=<缩放> z=<层级>
道具 <道具ID> @<锚点> z=<层级>
前景 <前景ID> opacity=<透明度>
镜头 <cut|crop|push> <参数> duration=<秒>
转场 <cut|fade> duration=<秒>
```

第一版只需要静态背景、静态人物状态、独立道具、一个前景层、裁切／轻推和硬切／淡入淡出。世界演出层与文字／选择 UI 层必须分开，避免以后每次换镜头都重排交互界面。本轮只记录目标，不修改代码。

## 2. 四档制作成本

| 档位 | 承载方式 | 使用原则 |
|---|---|---|
| A｜运行时复用 | 同一背景裁切、立绘进退场、透明度、轻微推拉、遮罩、灯光、雾气、音效 | 默认方案；不新增独立画面 |
| B｜复用状态 | 同一角色增加一个可跨场景使用的行为状态，或一个独立道具层 | 状态必须能在至少两个场次复用 |
| C｜关键静帧 | 一张经过一致性审查的单次关键画面或证物特写 | 只给核心动作、核心推理或核心传播画面 |
| D｜连续动画／一次性 CG | 多人连续接触、精确走位、转身、口型、长镜头或生成式视频 | 默认禁止；必须证明无法由 A—C 表达且值得单独审批 |

Demo 目标不是把每场做满，而是让绝大多数场次落在 A/B，仅把 C10 等真正的记忆点升到 C。当前没有场次必须使用 D。

## 3. AI 资源硬约束

1. **证据关键动作不能依赖生成式视频的中间帧。** 药盒是否往袖口收、吊绳长度与绕法、人物最后位置等都会进入推理；必须用经过人工核对的静帧、道具层或界面状态呈现，不能让时序漂移改变事实。
2. **不逐句生成角色图。** 每名角色优先使用 3—5 个跨场景行为状态，例如日常控制、听取观察、受压行动、作出决定、角色专属状态；不为每句台词单独生成表情。
3. **同一地点的远景、中景与特写必须从同一地点母版裁切或延展。** 不独立重生成三个“相似房间”，避免门、桌、铁梯、镜子和通道位置漂移。
4. **多人接触动作只保留动作峰值。** 拉人、扶人、抢药、按脉、递信等不做连续动画；采用动作前状态、一个关键静帧、动作后道具位置三段式切镜。
5. **群像不反复重生成。** C09—C16 共用一个“侧台事发现场母版”，人物以独立层或前景剪影进入；警方到场只改变门口光、人物层与封存道具。
6. **所有中文后期排版。** 报纸、采访函、稿纸、登记簿和界面文字均由 Godot／排版资产承载，AI 图中不得保留可读伪字。
7. **镜头不越过玩家知识。** 玩家没有选择的观察，不使用特写、插入镜头或角色反应偷偷展示；不同路线应切换可见层，而不是只在文字上假装没看见。
8. **不通过恐怖光效给答案。** 不用异常闪光、黑眼窝、反派逆光或突然特写标记嫌疑；不安来自构图、停顿、空间空缺、声音和旧印刷质感。
9. **标准板不能直接抠成最终立绘。** 当前标准板是角色设定合成图；从纸面直接抠人容易出现黑边、纸纹和衣摆光晕。运行立绘需要单独派生、脱底和边缘 QA。
10. **动作风险按“手部接触—多人同框—连续运动”递增。** 拿药盒、拉人、碰绳、翻纸等先拆成道具状态与静帧；多人同框尽量由角色层合成；不把逐帧 AI 视频当成基础产能。

## 4. 一个空间连续性母版＋六个可见地点母版

在生成玩家实际看到的背景前，先做一张不直接进游戏的“春和戏院空间连续性母版”，固定门前、前场、观众席、侧台通道、侧厅、铁梯与天桥的相邻关系、门向和人物可走路径。六张可见背景都必须服从这张空间母版，不能各自凭提示词独立生成。

| 母版 | 覆盖场次 | 建议可裁切区域 |
|---|---|---|
| 报馆编辑部 | S00—S02、C17—C22 | 编辑桌、赵敬文旧桌、排字入口／墙钟 |
| 春和门前与前场 | C01—C02 | 戏牌入口、登记处、账桌与前场通道 |
| 观众席与舞台 | C05—C07 | 侧座、舞台出口、前场出口、台口上方景片 |
| 侧台通道 | C03、C05—C16 | 侧台帘、贴墙铁梯、靠墙岔口、通往侧厅方向 |
| 侧厅 | C04、C08、C14、C16 | 约见桌、凉茶、蒙布镜、临时笔录桌 |
| 天桥与绳排 | C12、C15 | 铁梯口、向下视角、整排吊绳与单根绳特写 |

报馆与戏院分别共享纸张、雾气、灯光和色彩基准；远景、中景、特写尽量从对应可见母版裁切。母版数量是工作预算，不是已确认美术清单。正式制作前仍须为每项建立 asset task，并核对地点事实、尺寸、分层与目标导入路径。

## 6. 需要优先盲测的五处

### P1｜C03 阻拦动作

“踩上第一阶后被阿成拉下来”属于身体接触。先用鞋踩台阶特写、切到阿成挡住去路、衣料拉动声测试；若玩家无法理解，再考虑一张握袖关键静帧，不先做动画。

### P1｜C09 事发现场母版

这张母版必须成为 C09—C16 的空间权威。尸体、岔口、侧厅方向、铁梯与人物初始位置一旦锁定，后续不得按分支重新生成，否则推理空间会漂移。

### P0｜C10 药盒动作

这是证据动作、冲突动作和 Trailer 画面三合一，值得最高静帧预算；也最不能交给不稳定的连续生成。试玩必须确认玩家能复述“谁从哪里拿出药盒、做了什么、盒子最后在哪里”。

### P1｜C12 路线选择

路线差异必须来自可见空间和玩家选择，不靠完整步行动画。若玩家无法理解方位，应先改进场景母版、裁切与简图，不用文字提示或新增过场替代空间设计。

### P1｜C18—C21 核心循环

采访本、稿纸和次日报纸应共用同一套纸面视觉组件。最重要的传播镜头是“玩家选择的记录如何进入报道、再改变后果”，不是独立氛围 CG。

## 7. 以后每次剧情增强附加的制作字段

未来工作草案中，只要场次的动作、镜头或 UI 发生改变，制作审查至少回答：

```text
复用地点母版：
复用人物状态：
独立道具层：
运行时镜头／遮罩／音效：
是否需要关键静帧：
是否涉及身体接触或连续动作：
是否会因分支倍增资产：
玩家未走路线是否会被镜头泄露：
```

这组字段只用于识别成本和信息泄露，不自动成为新的玩法规则，也不要求每次都增加资源。

## 8. Demo 与宣传共用的四组镜头

资源优先投给既能试玩、又能截图或剪 Trailer 的真实交互画面：

1. S00：稿件被退回、署名被替换、玩家决定是否追春和；但 S00 当前仍有待确认结构，确认前不生产正式资产。
2. S01—S02：玩家在旧桌上决定带走原件还是抄录，让“信息与风险”一眼可见。
3. C09—C10：事发现场与药盒动作，承担第一桩死亡和核心证据冲突。
4. C18—C21：记录、判断、刊出、次日后果，完整展示本作“推理真相，再从自身利益决定公开什么”的循环。

C02—C08、C11—C16 和 C20—C22 优先服务实际游玩，不为 Trailer 另造一次性 CG。宣传应截取玩家真的会操作到的画面，避免正式制作出现第二套资产管线。

## 9. 当前资源缺口与顺序

1. 先锁地点母版及空间关系，再制作同地点的裁切镜头。
2. 从角色标准板派生可导入 Godot 的透明立绘与少量行为状态；不能直接把标准板当运行立绘。
3. 建立纸面 UI 母版和后期中文排版规则。
4. 建立药盒、采访函留底、旧报、草图、报纸和吊绳特写等独立道具层。
5. 在代码侧建立世界演出层与 UI 层分离的最小镜头解释器；未完成前，不把裁切、推镜和遮罩算作现成能力。
6. 最后才制作 C09 事发现场母版与 C10 药盒关键静帧。
7. 动画只在静态可理解性验证失败、且确实能改善核心体验时立项。

## 10. 待确认与风险

- 六个地点母版只是当前工作预算，尚未进入正式 manifest。
- C03 是否需要握袖关键静帧，必须由灰盒试玩决定。
- C10 是否采用一张还是两张关键静帧，取决于“藏向袖口”和“落地”能否由一张图加道具层说清。
- C18 的“先查一句”与 C19 的“刊出一句”视觉上必须明确分区，否则纸面组件复用可能反而让玩家混淆两步。
- 正式 UI、地点母版、立绘切图与道具图目前均未制作；本文件不能替代资产设计、生成、审查、导入和 QA。
- 当前 manifest 只有九项角色标准板记录；地点、运行立绘、道具、前景、灯光、镜头、动画和 UI 都没有正式资产条目。
- 角色漂移、多人同框污染、手部接触错误、地点空间漂移、中文伪字和连续动画闪烁是主要 AI 风险，必须在派生资产和导入前逐项 QA。
- 现有角色标准板存在已记录的角色级例外和画布尺寸差异；它们不妨碍作为身份锚点，但派生运行立绘时必须统一输出规格，不能反向改动已锁定角色长相。

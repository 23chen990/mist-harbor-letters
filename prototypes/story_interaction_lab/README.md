# 《雾港来信》全流程文字原型

> 类型：工作草案验证用的隔离原型，不接正式剧情数据，不代表正式实现或作者层定稿。

## 当前验证范围

原型不再把第一章压成一串功能按钮，而是以纯文字、色块和按钮连续呈现 v19 的完整场景过程：

`S00 → S01 → S02 → C01 … C16 → C17-20 → C21-22 → END`

- 固定正文、对白、材料与场次跳转放在 `story_flow.json`；`interaction_lab.gd` 使用通用 beat renderer，不为每个场次堆专用渲染函数。
- 叙事、纸面材料与所有 NPC 对白都逐句显示；点击当前内容卡才进入下一句，不会把整场对白同时铺开。
- 轮到沈砚舟说话时，界面先把完整原句显示为回答按钮；玩家点击后，该句才成为沈砚舟当前的对话卡，再点击对话卡继续。
- node 的可见正文全部读完后才出现观察、说话、查纸、犯忌、交件和发稿等真实选择；没有通用【继续】按钮。
- 每项选择前先显示可观察上下文，选择后先显示实际动作或反应，不发生无反馈的 choice → choice 跳转。
- S01 包含四份必读材料和可选旧草图；S02、C04、C14 连续保存采访函形态与实际控制人。
- C05—C09 保留位置锁定、热点取舍、侧厅路径与第一眼观察；未点内容不进入玩家证据。
- C10—C16 连续呈现药盒、传言、警方到场、笔录及天桥或主动追问分支。
- 天桥分支必须依次查看向下位置、整排吊绳与高收绳，最后一步才取得精确吊绳观察；上桥进入 C15，其他路线进入 C16。
- C17-20 在同一页持续显示传言、医师原话和固定首段，只列出当前实际解锁的完整末段稿句；选稿后形成完整稿件，允许更换一次，但不会自动交稿。
- C21-22 显示玩家实际刊出的完整稿件与一项主要后果；后果出现后只有【查收发簿】，点击后结束。
- 页面切换带有 180ms 输入隔离，避免双击内容卡或按键释放误触下一句及不可逆选项；隔离结束后恢复键盘焦点。
- 默认玩家界面只显示作品名、当前场内位置、当前一句内容与当下可执行选择；不显示草案版本、内部场次编号、阶段名、调试标题或重开快捷键说明。

## 知识边界

- `1917` 旧报只作为玩家读过的报道原文，不进入已查明事实。
- 回信试探只保存沈砚舟说过的话，不认证回信存在。
- 药盒内容和林怀安死因均不由系统认证。
- C11 只呈现“有心疾”如何传成“旧疾发作”，不会直接解锁 `medical_boundary`；该稿句必须在 C16 主动追问许济川后出现。
- C14 单独保存玩家实际说进笔录的到场批次与第一眼内容，不把全局观察自动视为警方知情。
- 方仲山离桌稿句同时要求 C06 亲见离桌与 C16 主动追问；“侧厅约见＋倒地岔口”弱路线稿句只在没有更强路线材料时出现。
- 动态稿句暂沿用隔离原型排序，最多显示三条；这只是灰盒版面占位规则，不是正式优先级决策。

## 运行

双击仓库根目录的 `打开交互试验场.command`。重新启动原型会从开场开始，并清空当次材料、函件、位置、观察、警方知情、追问、选稿、交稿和结束状态。

窗口保持无调试标题栏：右上角提供最小化、放大 / 还原和关闭；拖动作品名可移动窗口，双击作品名可放大 / 还原，右下角拖柄可自由调整窗口大小。界面最小支持 960×540，并会随窗口尺寸扩展正文区域。

## 自动测试

```bash
prototypes/story_interaction_lab/运行全部测试.command
```

三组测试覆盖：

1. `story_flow.json` 合法性、稳定场次 ID、完整场次集合、跳转 target 与数据驱动边界；
2. 知识、证据、函件控制、警方知情、C16 追问、稿句来源、一次换稿、交稿、后果和发簿状态；
3. 天桥 / 非天桥两条完整端到端路径、逐句内容卡、沈砚舟原句确认、NPC 不成组显示、未读草图边界、完整稿件、跨页输入隔离、单一后果及重开清空。
